# 요구사항 문서: 매너볼트 (Manner-Volt)

## 1. 의도 분석 요약
- **사용자 요청**: res.md 기획서(그린라이트팀, 전기차 충전 현황 앱)를 기반으로 Pleos Connect와 연동되는 앱을 만든다.
- **요청 유형**: New Project (Greenfield)
- **범위 추정**: Multiple Components (차량 앱, 백엔드, 공공 API 연동, 시뮬레이터)
- **복잡도 추정**: Complex (차량 데이터 검증, 상태 관리, 신뢰도 점수, 외부 API)
- **요구사항 깊이**: Standard~Comprehensive. 비즈니스 규칙과 보안 확장이 켜져 있어 추적성을 유지한다.
- **참고**: 기획서 5항(개발 계획)은 공란이며, 구현 완료 후 실제 구현 기준으로 초안을 작성한다.

### 확인이 필요한 가정 (사용자가 짚어야 할 부분)
- **Pleos SDK의 실제 API는 확인하지 못했다.** Pleos Connect가 Android Automotive OS 기반이라는 점만 확인했다. 그래서 차량 데이터 접근은 `VehicleDataSource` 같은 인터페이스 뒤에 두고, 시뮬레이터와 Car API 구현을 교체할 수 있게 한다. SDK 문서를 받으면 Pleos 전용 구현만 채우면 된다.
- 충전기 분리, 충전 상태 등 일부 차량 속성은 표준 Car API로 제공되지 않을 수 있다. 제공되지 않으면 시뮬레이터 값으로 대체한다.
- 공공 API 명세(엔드포인트, 필드, 갱신 주기)는 구현 단계에서 실제 호출로 확인한다.

## 3. 기능 요구사항

### FR-1 출차 시각 설정 (기획서 기능 ①)
- FR-1.1 충전 시작을 감지하면 배터리 잔량, 목표 충전량, 충전 출력, 외기 온도, 지하/실외 구분으로 충전 완료 예상 시각을 계산한다.
- FR-1.2 충전 완료 예상 시각에 운전자의 과거 출차 지연 평균을 더해 출차 예정 시각을 추천한다.
- FR-1.3 운전자는 하차 전 차량 화면에서 추천 시각을 확인하고 확정하거나 직접 수정한다.
- FR-1.4 확정 후에도 변경할 수 있고, 변경 시 대기자에게 알림이 간다.
- FR-1.5 과거 기록이 없으면 기본 지연값(설정 파일)을 쓴다.

### FR-2 충전 종료 예정 공유 지도 (기능 ②)
- FR-2.1 충전소 배치도에 충전기별로 "충전 완료 예상 / 출차 예정", 이용 가능, 사용 중, 운영 중지 상태를 표시한다.
- FR-2.2 주변 충전소 목록을 보여 주고, 공공 API 정보(위치, 충전기 타입, 출력, 운영기관, 상태)를 함께 표시한다.
- FR-2.3 차량이 확정한 출차 시각이 없는 충전기는 공공 API의 현재 충전 시작 시각만 표시하고, "예정 시각 미공유"로 구분한다.
- FR-2.4 운전자의 위치는 다른 사용자에게 공개하지 않는다.

### FR-3 대기 등록과 알림 (기능 ③)
- FR-3.1 사용 중인 충전기에 대기 등록과 취소를 할 수 있다.
- FR-3.2 충전기당 대기열은 등록 순서로 처리하며 최대 인원은 설정 값으로 한다.
- FR-3.3 출차 예정 시각이 가까워질 때(설정 값, 기본 15분 전)와 변경될 때 차량 화면에 알림을 보낸다.

### FR-4 실제 출차 확인 (기능 ④)
- FR-4.1 충전 종료 데이터, 충전기 분리, 차량 위치 이동(충전 구역 이탈)을 종합해 출차를 판단한다.
- FR-4.2 출차 확인 시 충전기를 "이용 가능"으로 바꾸고 대기자에게 알린다.
- FR-4.3 도착한 대기자가 "자리 비어 있음/아직 있음"을 누르면 차량 데이터와 대조해 판단 오류를 줄인다. 불일치는 기록한다.
- FR-4.4 위치 정보는 충전 구역 이탈 판단에만 쓰고 서버에는 이탈 여부만 보낸다. 원 좌표는 보내지 않는다.

### FR-5 매너볼트 신뢰도 (기능 ⑤)
- FR-5.1 약속한 출차 시각과 실제 출차 시각의 차이로 점수를 올리거나 내린다. 초기 100점이며 모든 값은 설정 파일로 조정한다.
- FR-5.2 매너볼트는 다음 이용자가 출차 예정 시각을 얼마나 믿을지 판단하는 참고 정보로만 쓴다. 점수에 따른 대기 우선권이나 대기 제한은 두지 않는다. (2026-11-12 변경)
- FR-5.3 유예 시간이 지나도 출차가 확인되지 않으면 대기자에게 근처의 다른 충전기를 자동으로 안내한다.
- FR-5.4 누적 기록은 FR-1.2의 개인별 지연 보정에 사용한다.

### FR-6 시연용 시뮬레이터
- FR-6.1 기획서 4항 시나리오(운전자 A와 B)를 처음부터 끝까지 재현하는 시뮬레이션 모드를 제공한다.
- FR-6.2 가상 차량 데이터(배터리, 충전 상태, 충전기 분리, GPS)를 시간 배속과 함께 제어할 수 있다.

### FR-7 공공 API 연동
- FR-7.1 백엔드가 한국환경공단 충전소 정보 API를 호출하고 결과를 캐시한다. 호출 키는 서버에만 둔다.
- FR-7.2 공공 API의 충전기(`statId`+`chgerId`)와 우리 서비스의 출차 정보를 같은 충전기 ID로 결합한다.
- FR-7.3 API 호출 실패나 제한 초과 시 캐시와 샘플 데이터로 대체하고, 화면에 데이터 기준 시각을 표시한다.

## 4. 비기능 요구사항

### NFR-1 보안 (Security Baseline 전 규칙 적용, 로컬 서버 기준으로 조정)
- 백엔드는 시연 촬영용 로컬 서버이며 외부에 공개하지 않는다. 서버는 localhost(에뮬레이터는 10.0.2.2)에만 바인딩한다.
- 공공 API 키와 모든 비밀 값은 소스나 APK에 넣지 않고 `.env.local`(git 제외)에서 읽는다. 서버 외부로 응답하거나 로그에 남기지 않는다. (SECURITY-12)
- 저장소는 로컬 DB 파일이며 저장소 파일은 git에서 제외한다. 외부에 공개되지 않는 로컬 환경이므로 저장 시 암호화와 TLS는 설계 단계에서 N/A 또는 문서화된 예외로 확정한다. (SECURITY-01)
- 서버 요청 로그는 구조화 형식으로 파일에 남기고 PII, 토큰, 정확한 위치를 기록하지 않는다. 클라우드 로그 서비스, 90일 보관, 경보는 로컬 환경에서 적용하기 어려워 설계 단계에서 N/A 또는 예외 사유를 기록한다. (SECURITY-02, 03, 14)
- 모든 API 입력은 스키마 검증, 길이 제한, 허용 목록 검증을 한다. (SECURITY-05)
- 익명 식별이라도 모든 엔드포인트는 인증이 필요하다. 기기 등록 후 서버가 서명한 토큰을 발급하고 매 요청마다 검증한다. 객체 단위 권한(내 출차 정보만 수정)을 검증한다. (SECURITY-08)
- 서버 API에는 속도 제한을 적용한다. 오용 시나리오(허위 출차 확인, 대기열 독점, 점수 조작)를 설계 문서에 포함한다. (SECURITY-11)
- 클라우드 IAM이 없으므로 SECURITY-06은 N/A이다. 서버는 필요한 파일과 포트만 사용한다.
- 의존성은 고정하고 취약점 스캔 단계를 둔다. (SECURITY-10)
- 오류 응답은 일반 메시지만 반환하고, 오류 시 접근을 거부하는 방향(fail closed)으로 동작한다. 전역 오류 처리기를 둔다. (SECURITY-09, 15)
- 중요한 데이터 변경(출차 시각, 점수)은 변경자, 시각, 이전/이후 값을 감사 기록으로 남긴다. (SECURITY-13)
- SECURITY-04(HTTP 보안 헤더)는 HTML을 서비스하지 않으면 N/A이다. SECURITY-07(네트워크 구성)은 localhost에만 바인딩하는 로컬 서버라 방화벽 규칙이 없으면 N/A이다. 설계 단계에서 확정한다.

### NFR-2 개인정보
- 차량 위치는 기기 안에서만 처리하고, 서버에는 충전 구역 이탈 여부만 보낸다.
- 익명 ID는 차량 식별번호(VIN)나 번호판 같은 실제 식별자를 쓰지 않고 앱이 만든 무작위 값으로 한다.

### NFR-3 성능과 사용성
- 차량 화면 조작은 운전 중 방해를 줄이기 위해 큰 터치 대상과 간단한 흐름을 쓴다. 하차 전 출차 시각 확정은 2번의 터치 안에 끝나야 한다.
- 지도(배치도) 상태는 서버 반영 후 최대 수 초 안에 갱신한다. 정확한 목표치는 NFR 단계에서 정한다.

### NFR-4 테스트 (PBT Partial 적용)
- 테스트 프레임워크로 Kotlin은 Kotest Property Testing 등 PBT 프레임워크를 선택한다. (PBT-09)
- 순수 함수(충전 완료 예측, 출차 시각 추천, 매너볼트 점수 계산)와 직렬화 왕복에 PBT를 적용한다. (PBT-02, 03, 07, 08)
- PBT 실패 시 시드와 축소된 입력을 출력한다.
- 핵심 시나리오(기획서 4항)는 예시 기반 테스트로도 고정한다.
- 사용자가 별도로 요청하기 전까지 그 밖의 테스트는 최소로 하고, Build and Test 단계에서 실행 지침을 제공한다.

### NFR-5 이식성
- Pleos 전용 코드는 인터페이스 뒤에 분리한다. SDK 접근이 가능해지면 구현체만 교체한다.

## 5. 범위 밖 (Out of Scope)
- 스마트폰 보조 앱
- 결제, 충전 예약 결제, 충전 제어
- 충전 구역을 차지한 비충전 차량 신고 기능 (기획서 6항의 향후 확장)
- 클라우드 배포, 외부 공개 서버, 실제 운영 배포, 실서비스 부하 대응, 공모전 접수 서류 작성 및 서명 (기획서 5항 초안만 제외하고 제출 서류는 대상 아님)

## 6. 성공 기준
- 기획서 4항 시나리오 ①~④가 시뮬레이션 모드에서 끝까지 재현된다.
- 공공 API로 가져온 충전소 정보가 목록에 표시된다. (API 키 제공 시)
- 안드로이드 Automotive 에뮬레이터에서 로컬 서버와 연동해 실행되고, 시연 영상을 촬영할 수 있다.
- APK가 빌드된다. (로컬 서버 주소는 설정 값이며, 영상 촬영 PC 밖의 기기에서는 서버에 접속하지 못할 수 있다.)
- 보안 확장 규칙이 설계와 코드 단계에서 충족된다.

## 7. 변경 요구사항 (2026-11-12, 핵심 구조와 공정성 규칙)

결정 사항: 야간 모드 없음, 약속 허용 5분 유지, 연장 최대 2회 + 대기자 알림, 알림은 차 화면에서만.

### FR-8 충전기 자동 매칭 (변경 항목 1)
- FR-8.1 충전기를 꽂은 시각 기준 ±5분 안에 같은 충전소에서 공공데이터 상태가 '충전 중'으로 바뀐(`nowTsdt`) 충전기 중 아직 매너볼트 약속이 없는 충전기를 후보로 찾는다.
- FR-8.2 후보가 1개면 "3번 충전기 맞나요?"를 한 번만 묻고, 여러 개면 후보 목록에서, 없으면 전체 충전기 목록에서 고른다.
- FR-8.3 지하 GPS에 의존하지 않는다. 위치는 출차 판단(구역 이탈)에만 쓴다.

### FR-9 충전 완료 예상의 단계적 보정 (변경 항목 2)
- FR-9.1 꽂은 직후에는 충전기 출력(공공데이터)과 현재 배터리 %로 대략 계산해 바로 보여 주고 '추정'으로 표시한다.
- FR-9.2 4분 이상 지나고 배터리가 1%p 이상 오르면 실제 상승 속도로 다시 계산한다.
- FR-9.3 다시 계산한 완료 시각이 5분 이상 달라지면, 확정 전에는 자동 반영하고 확정 후에는 "예상 시간이 바뀌었어요. HH:MM으로 변경할까요?"를 묻는다. 이 변경은 연장 횟수에 포함하지 않는다.

### FR-10 알림 역할 분리 (변경 항목 3)
- FR-10.1 약속(출차 시각 확정)은 꽂는 순간 차에서, 확인(빈자리 보기)은 운전 중 차에서 한다.
- FR-10.2 알림은 차 화면에서만 보여 준다. 차에 없는 동안 온 알림은 다음 탑승(화면 진입) 때 모아 보여 준다.
- FR-10.3 휴대폰 알림(블루링크, 문자)은 범위 밖이다. Pleos의 휴대폰 푸시 가능 여부는 확인이 필요하다.

### FR-11 퇴근길 도착 비교 (변경 항목 4)
- FR-11.1 내비 도착 예정 시간(Pleos NaviHelper `DestinationInfo.remainTime`)과 단지 충전기가 비는 시각을 비교해 "집 도착 22:58 · 3번 충전기 23:10 빔 (매너볼트 104V) → 도착 후 약 12분 대기"처럼 보여 준다.
- FR-11.2 대기 등록 시 도착 예정 시각을 함께 보내고, 대기 1순위는 이 시각을 기준으로 자리를 맡는다.

### FR-12 출차 확인과 점수 공정성 (변경 항목 5~8)
- FR-12.1 출차 확정 = 충전기 분리(충전 종료) + 기어 D/R + 충전 구역 이탈. 일부만 있으면 '이동 감지'로 둔다. 약속 허용은 5분이다.
- FR-12.2 출차 예정은 '예상 완충 시각 + 최대 30분'까지만 고를 수 있다. 법정 충전 방해 기준(급속 1시간, 완속 14시간)을 넘는 시각은 고를 수 없다. 법령 원문 재확인이 필요하다.
- FR-12.3 연장은 확정 시각 전에만, 최대 2회, 한 번에 최대 30분이다. 대기자가 있어도 연장할 수 있지만 대기자에게 바로 알리고, 연장한 충전은 약속을 지켜도 보너스(+2)를 받지 않는다.
- FR-12.4 찜(대기)은 한 사람당 1개, 순번은 찜한 순서. 충전기가 빈 뒤 '도착 예정 시각(없으면 빈 시각) + 10분' 안에 오지 않으면 자동 취소하고 다음 순번에게 알린다.

### FR-13 개인정보와 운전 중 안전 (변경 항목 9, 10)
- FR-13.1 다른 차량은 차량 번호 없이 '충전기 번호 + 매너볼트'만 보여 준다.
- FR-13.2 기어가 D/R이면 터치 요소 없는 카드 한 장으로만 보여 주고, 새 알림은 음성(Pleos TTS)으로 읽는다.

### FR-14 매너볼트를 쓰지 않는 차량 (변경 항목 11)
- FR-14.1 약속이 없는 충전기는 공공데이터 충전 시작 시각으로 계산한 완료 예상만 '추정' 라벨로 보여 주고 매너볼트는 표시하지 않는다.
